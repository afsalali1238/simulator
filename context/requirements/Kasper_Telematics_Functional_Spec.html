Kasper GPS-as-a-Service
Functional Specification

What the GPS product does, for whoever operates or holds a device on it — features, roles and the flows that connect them. Written for Product and Engineering to work from the same page. Scoped to GPS-as-a-Service only.

00Scope and audience

This document answers "what does the product do" — features, roles, and the flows a user or a device moves through. Written for Product and Engineering to work from the same page.

01The product

Kasper's GPS-as-a-Service (Product 03) is the only product in scope here. It is a standalone product in its own right — not a feature bolted onto the marketplace, and not limited to vendors who already work with Kasper. Any fleet or equipment owner can buy it directly.

Product 03 · Live pilot

GPS-as-a-Service

Across three tiers (§02): a Teltonika device hardwired to a truck or machine, reporting position, ignition and — on the two higher tiers — engine hours, fuel and RPM off the machine's CAN bus, without anyone needing to remember to do anything.

Why buyers buy it: live fleet visibility, maintenance alerts, fuel-theft detection, and proof of location for insurance and client disputes — the same value whether the buyer is a marketplace vendor or a fleet owner with no other relationship to Kasper.

Why Kasper builds it: recurring, device-based revenue independent of marketplace job volume. Where the buyer is also a marketplace vendor, a device bolted to their asset is additionally the platform's strongest switching cost — but that's a bonus of the go-to-market, not what the product is.

02Device tiers — what each one can promise

Not every instrumented asset produces the same data, and this is the single fact that determines which features apply to which asset. All three tiers share the same base hardware (FMC130); the tier is set by which CAN adapter — if any — sits behind it, and that is what actually determines what the device can report.

TierHardwareFleet roleReportsCannot do
Tier 3 FMC130 + ALLCAN300
the only adapter that reaches construction and agricultural machinery		 Excavators, cranes, generators, boom lifts, backhoes, forklifts — every asset that goes out on a utilisation-billed hire contract Position, speed, ignition, movement, engine hours, fuel level, RPM, fault codes, voltage, accelerometer Cannot produce ECU engine hours on a machine with no supported CAN program number, or where the machine does not broadcast the parameter — the vendor's own fallback is an ignition counter, which is not billing evidence. Verify per make/model/year before quoting. See note below.
Tier 2 FMC130 + LVCAN200
fleet-analytics tier		 Standard trucks and light-vehicle fleets — the "fleet analytics" tier Position, speed, ignition, movement, plus some CAN-sourced data on supported vehicle profiles No ECU engine hours. The LVCAN200 parameter set does not carry them; what is available is an ignition-derived estimate, which every tier has and which is not billing-grade — it cannot carry a utilisation contract. See §04.6.
Tier 1 FMC130 only
basic tracking tier		 Flatbed trailers, tipper trucks, light vehicles — assets that only need to be seen, not billed by the hour Position, speed, ignition, movement No engine hours, no fuel level, no RPM, no fault codes. No CAN adapter fitted, no ECU access of any kind.

The consequence that has to be a product rule, not a hope

A Tier 1 asset can never carry a utilisation (billable-hours) contract. There is no ECU reading to bill from, and no estimate that survives a client challenge. It is real product — verified arrival, verified departure, route history, geofencing — just not billable-hours product.

Capability is the pair, not the tier alone. A Tier 3 device on a machine whose make/model/year has no supported CAN program number degrades to Tier 1's contract: position and ignition only, no engine hours. Same commercial outcome as selling the wrong tier — invisible until the data arrives. The system must refuse to open a utilisation-billed assignment on an asset that cannot source ECU hours; this has to be a hard constraint, not a report someone checks after the fact.

Upgrade path — the same FMC130 stays on the machine throughout

Tier 1 → Tier 2 is adding an LVCAN200 adapter to an already-installed FMC130. Tier 2 → Tier 3 is swapping that LVCAN200 for an ALLCAN300. The base device never changes, so a tier upgrade is a field visit to the adapter, not a re-install.

03Who uses this

Five roles, each scoped by the same underlying rule: a role sees an asset only for the period it was actually theirs, enforced through dated assignment windows rather than whoever currently holds the asset.

Client master

Every asset on hire to their company, across all projects and sites, for exactly the periods that were theirs.

Client site user

Only the assets assigned to their specific site. Cannot see another site on the same contract.

Vendor / fleet owner

Every asset they own, across every client that has ever hired it, all the time. This is the paying surface for Product 03 — whether the account is an existing marketplace vendor or a fleet owner buying GPS-as-a-Service standalone, they see the whole life of their own equipment, wider than any client's view of it.

Kasper ops

Everything, for day-to-day operations — provisioning, install verification, alert triage.

Kasper admin

Everything, with every cross-tenant access written to an audit log.

A rule the product must never break

Some devices can show a fuel figure without any CAN access at all — GPS receivers can estimate fuel from movement patterns. That estimate and an ECU-sourced reading must never appear as the same field. Every fuel figure the product shows carries a visible source label — "ECU" or "estimated" — everywhere it's displayed, not just in a tooltip. An estimate presented as a reading is the kind of thing that loses a billing argument.

Immobiliser is excluded, deliberately, not deferred

Technically available as a digital-output command on the device. Commercially it is a liability the product does not take on: legal review, a hard interlock preventing activation while the asset is in motion, two-person authorisation, and a dedicated audit trail would all be prerequisites before it could even be considered. It is not "just another command," and it stays off the roadmap until someone deliberately reopens it.

05Core user flows

Device commissioning — new hardware onto a fleet asset

1
VendorAgrees to the hardware upgrade during an ops call, or a new asset joins the fleet.
2
Kasper opsChecks the asset's make/model/year against the supported CAN program number list before scheduling — this decides whether it can ever carry a utilisation contract.
3
Auto-electricianInstalls the device, wires ignition sense and CAN adapter, verifies sky view.
4
Kasper opsConfirms live data — including engine hours — is reaching the platform before signing off the install. Skipping this step is what turns a five-minute fix into a second site visit.
5
PlatformDevice provisioned, billing activated, asset appears on the fleet dashboard and the vendor's device subscription begins.

Live monitoring and a geofence alert

1
Client / Kasper opsOpens the fleet map — every asset they're entitled to see, live, with status.
2
AssetCrosses a defined site boundary.
3
PlatformFires a geofence event, checks it isn't a replay of a stale record, and delivers via the configured channel.
4
RecipientGets a WhatsApp message or in-app alert — "Truck 3 entered Site A" — with the event logged for the audit trail.

Utilisation billing and a dispute

1
PlatformTracks engine-hour deltas continuously against the current hire assignment window.
2
PlatformAt period close, computes the delta, flags any unobserved gaps explicitly, and seals the utilisation period — no further edits possible.
3
Kasper / VendorExports the Monthly Utilisation Certificate — hours, idle time, distance, disclosed gaps — and sends it to the client.
4
ClientDisputes a figure. Kasper pulls the sealed record — same certificate, same numbers, every time, because the underlying period cannot have been silently edited.

Maintenance alert

1
PlatformEngine hours cross a configured service threshold for an asset.
2
PlatformSends a WhatsApp alert to the vendor — "Truck 3 due for service in 2 weeks."
3
VendorBooks service proactively, ahead of a breakdown.

Client tracking link (single job)

1
PlatformGenerates a signed, expiring, single-job tracking link when a job or hire begins.
2
ClientOpens the link — no login — and sees live position and verified arrival/departure for that one asset or job.
3
PlatformRevokes the link automatically when the job closes. A permanent or unsigned link is treated as a standing exposure, not a convenience.

06Screens and surfaces

Nine screens make up the product, confirmed against the tech team's feature spec. Each is tier-gated where the underlying data is tier-gated — a locked screen stays visible with an upgrade prompt rather than disappearing, so a buyer always knows what they're not yet paying for.

Five of the nine already run as a working prototype

Fleet Map, Fuel, Maintenance, Geofences and a Cost & ROI view exist today on Kasper brand tokens, running against mock data shaped to match the real telemetry format — screenshots below. Vehicle Detail, Trip History & Playback, Alerts Center, Client Tracking Link and Timesheet are confirmed in the spec but not yet built; Cost & ROI is in the prototype but not in the confirmed 9-screen spec below and needs a product call on whether it stays. 07Glossary

FMC130The base GPS hardware across all three tiers. On its own (Tier 1) it reports position, speed, ignition and movement only.
Tier 1 / 2 / 3Kasper's capability tiers, set by which CAN adapter, if any, sits behind the FMC130. See §02.
LVCAN200The CAN adapter behind Tier 2 (fleet analytics). Wired to the vehicle's CAN lines — it is not an OBD plug-in. Teltonika lists it for light vehicles including EVs, trucks, buses and coaches; it does not cover construction or agricultural machinery. Reads fuel, mileage, RPM, coolant, oil pressure and door status. It does not carry ECU engine hours — see §02 and §04.6.
ALLCAN300The CAN adapter behind Tier 3 (heavy equipment). The only adapter Teltonika lists for special transport — utility, forest and construction machinery — and the only route to ECU engine hours, fault codes and a utilisation contract. What it actually delivers on a given machine still depends on that machine's program number and on the parameter being broadcast; neither is guaranteed. It reads; it never controls the machine.
Program numberTeltonika's configuration for decoding a specific machine make/model/year. Per-model, not universal, and must be confirmed against the real fleet before installs are scheduled.
Utilisation certificateThe monthly statement of engine hours, idle time, distance and disclosed gaps for a hire period. Sealed once issued.
Assignment windowThe dated record of which customer, project or vendor an asset belonged to over a period. Basis of both access control and billing attribution.
SourceThe field distinguishing an ECU reading from a GNSS estimate on any given value. Never merged, never inferred.
Pooled tenancyOne shared platform with row-level access separation, rather than dedicated infrastructure per customer.
